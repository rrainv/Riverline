# Engine and numbers (loads when you touch engine or domain files)

1. `engine/` has no DOM, `window`, storage or network access. It runs in a worker and is written in strict TypeScript.
2. When mining logic from the old repository (`C:\Users\sjzns\Projects\poker-gto-app`, strictly read-only), do not copy legacy JS verbatim: inspect its contracts, invariants, and behaviour tests, rewrite cleanly in TypeScript inside `engine/`, and port the behaviour tests + `tools/eqexact.py` golden tests to prove equivalence. Record the inspected source commit and target module in `docs/ENGINE_PROVENANCE.md`.
3. Preserve versioned data contracts unless the owner approves a migration. If old behaviour looks wrong, add a failing test that states the expected behaviour, log it in `docs/BUG_INBOX.md`, and ask. Do not change it silently.
4. Every figure the interface shows comes through `src/engine-api`. No arithmetic on poker quantities in `src/ui/`.
5. Golden values are generated by `tools/eqexact.py` or the engine's exact routines and stored with the command that produced them. Never type one in.
6. Exact when cheap; otherwise sampled with a seed, a sample count and a stated margin, labelled Estimated.
7. Decision economics: the facing size is wager-to; the call amount is the incremental, stack-capped price; an ante is dead money.
8. Range maths: inclusion weight, action probability, conditioned reach and uncertainty are different values. Joint sampling rejects colliding card sets.
9. Recorded evidence is immutable. Corrections are appended with lineage.
10. Versioned contracts (hand state, table rules, replay, saved objects) are not flattened or migrated without the owner's yes.
11. Requests carry an ID and can be cancelled; stale results are dropped by the caller.
12. Bots receive only what their seat could know. A hand in progress is embargoed from analysis.
